# 챱츄(PawRoute) 개발 페이지 및 기능 명세

> 기준일: 2026-09-20
> 기준 소스: 현재 `chapchu-front` 저장소의 Next.js App Router, 화면 컴포넌트, API 모듈 및 테스트
> 범위: 사용자가 접근하는 페이지, 페이지 안에서 전환되는 하위 화면·모달, 개발 전용 화면, 현재 라우트에 연결되지 않은 구현 화면

## 1. 서비스 개요

챱츄(PawRoute)는 반려동물과 함께하는 여행을 위해 현재 위치와 날씨를 확인하고, 출발지·도착지 및 반려동물 정보에 맞는 여행 코스를 추천받아 여행 기록과 사진을 남길 수 있는 모바일 우선 웹 애플리케이션이다. 완성한 여행은 앨범으로 확인하거나 여행 리뷰 게시글로 공유할 수 있다.

주요 기술은 Next.js App Router, React, TypeScript, Tailwind CSS, Zustand, Axios, TMAP, 기상청 날씨 API이며, 화면은 최대 너비 430px의 모바일 셸을 기본으로 제공한다.

## 2. 공통 내비게이션과 접근 제어

### 2.1 공통 하단 내비게이션

로그인 후 메인 영역에서는 다음 5개 탭을 제공한다.

| 탭 | 경로 | 기능 |
| --- | --- | --- |
| 홈 | `/home` | 현재 위치, 날씨, 주변 추천 장소, HOT 게시글 확인 |
| 게시판 | `/community` | HOT·자유게시판·여행 리뷰 조회 및 커뮤니티 활동 |
| 지도 | `/map` | 여행 코스 생성부터 진행·완료까지의 전체 플로우 |
| 앨범 | `/album` | 완료한 여행과 사진, 후기 확인 |
| 내정보 | `/my` | 프로필, 반려동물, 작성 콘텐츠 및 계정 관리 |

- 지도 플로우와 게시글 작성 화면에서는 집중 동선을 위해 하단 내비게이션을 숨긴다.
- 앨범 탭을 이미 선택한 상태에서 다시 누르면 앨범 목록 최상단으로 스크롤한다.
- 메인 영역은 인증된 세션만 접근할 수 있다. 앱 진입 시 액세스 토큰이 없으면 HttpOnly 쿠키 기반 `/auth/refresh`로 세션 복원을 시도하고, 실패하면 `/login`으로 이동한다.
- 개발 환경에서는 테스트 계정으로 시작한 메모리 기반 데모 세션도 메인 영역 접근을 허용한다.

### 2.2 공통 인증·세션 동작

- 액세스 토큰은 브라우저 영구 저장소가 아닌 Zustand 메모리에만 보관한다.
- 인증 API의 읽기 요청이 `401`을 반환하면 토큰 갱신 후 한 번 재시도한다.
- 쓰기 요청은 명시적으로 안전한 재실행이 허용된 경우가 아니면 토큰 갱신 후 자동 재전송하지 않아 중복 생성을 방지한다.
- 로그아웃 또는 세션 변경 시 위치, 여행 진행 상태, 반려동물 상태, 게시글 임시 초안 등 세션 범위 데이터를 초기화한다.

## 4. 공개·인증 페이지

### 4.1 스플래시 — `/`

서비스 첫 진입 화면이다.

- PawRoute 로고, 서비스명, 소개 문구, 로딩 애니메이션을 표시한다.
- 2.2초 후 자동으로 `/onboarding`으로 이동한다.
- 모바일 셸 안에서 표시된다.

### 4.2 온보딩 — `/onboarding`

서비스 핵심 가치를 3개의 슬라이드로 소개한다.

1. 반려동물 동반 가능 여행지 탐색과 코스 생성
2. 출발지·도착지, 날씨, 반려동물 성향, 이동 거리를 고려한 경로와 중간 거점 추천
3. 여행 사진·노트 기록, 앨범 저장, 커뮤니티 및 SNS 공유

제공 기능:

- `다음` 버튼과 페이지 인디케이터로 앞뒤 슬라이드를 이동한다.
- `건너뛰기` 또는 마지막 슬라이드의 `시작하기`를 누르면 `/login`으로 이동한다.
- 슬라이드 전환 애니메이션과 애니메이션 중 중복 입력 방지를 제공한다.

### 4.3 로그인 — `/login`

- `Google로 계속하기`를 누르면 BFF의 `/auth/login`으로 이동한다.
- 프런트엔드 현재 origin의 `/auth/callback`을 redirect URL로 전달한다.
- OAuth 시작 시 일회성 트랜잭션 표식을 `sessionStorage`에 기록한다.
- 로그인 시작 실패와 이전 로그아웃 실패 안내를 화면에 표시한다.
- 비프로덕션 환경에서는 `테스트 계정으로 로그인`을 제공하며 `/setup?mode=demo`로 이동한다.

### 4.4 인증 콜백 — `/auth/callback`

Google OAuth 결과를 안전하게 해석하는 중간 처리 화면이다.

- URL의 민감한 콜백 파라미터를 읽은 직후 주소를 `/auth/callback`으로 정리한다.
- OAuth 시작 탭에 저장한 일회성 트랜잭션 표식이 없거나 결과가 올바르지 않으면 콜백을 거부한다.
- 기존 사용자: 액세스 토큰을 메모리에 저장하고 `/home`으로 이동한다.
- 신규 사용자: `registration_token`을 메모리에 저장하고 `/setup`으로 이동한다.
- 실패 시 세션과 로그인 후 목적지를 초기화하고 `로그인으로 돌아가기`를 제공한다.

### 4.5 회원가입·초기 설정 — `/setup`

신규 사용자는 3단계로 필수 정보를 입력한다. 개발 데모 세션도 같은 UI를 사용하지만 실제 가입 API를 호출하지 않고 완료 후 홈으로 이동한다.

#### 1단계: 기본 정보

- 닉네임 입력 및 서버 중복 확인
- 선호 테마 복수 선택
- 선호 지역 복수 선택
- 선호 이동수단 복수 선택
- 필수 입력이 빠졌을 때 누락 항목 모달 표시

#### 2단계: 반려동물 정보

- 반려동물 이름, 견종, 크기(소형·중형·대형), 나이, 선호 활동 입력
- 견종 검색형 콤보박스 제공
- 반려동물 여러 마리 추가 및 추가 취소
- 각 반려동물의 필수 입력과 나이 형식 검증

#### 3단계: 위치정보 이용 동의

- 개인위치정보 수집·이용 안내
- 기상청, 한국관광공사 TourAPI, SK텔레콤 TMAP에 대한 제3자 제공 안내
- 수집·이용 및 제3자 제공 동의를 모두 완료해야 가입 가능
- 이 단계에서는 동의 여부만 저장하고, 기기 위치 권한은 실제 기능 사용 시 별도로 요청

연동 및 예외 처리:

- 가입 선택지는 `/preferences/options`, `/breeds`, `/activities`에서 병렬 조회한다.
- 닉네임 중복 확인은 `/users/nickname/availability`를 사용한다.
- 실제 가입은 `/auth/signup`에 사용자 선호와 반려동물 목록을 한 번에 전송한다.
- 가입이 끝나면 새 Google 로그인을 시작해 최초 액세스 토큰을 발급받는다.
- 등록 토큰 만료, 닉네임 충돌, 선택지 변경, 네트워크 오류를 각각 안내하고 필요한 단계로 되돌린다.

## 5. 홈 — `/home`

로그인 직후 핵심 정보를 모아 보여주는 대시보드다.

### 제공 기능

- 현재 위치 지도
  - 페이지 진입 시 고정밀 위치 조회를 자동 요청한다.
  - 위치가 확보되면 현재 위치와 정확도를 표시한다.
  - 위치 권한 거부 또는 낮은 정확도 등 실패 시 대구 수성구 기본 위치를 사용하고 사유를 표시한다.
- 현재 날씨
  - 위·경도를 기상청 격자 좌표로 변환해 `/api/weather/current`에서 조회한다.
  - 기온, 날씨 상태, 풍속, 습도, UV 지수, 산책 조언을 표시한다.
  - 날씨 카드만 독립적으로 다시 시도할 수 있다.
- 여행 시작 CTA
  - 등록된 반려동물 이름을 반영한 안내를 표시한다.
  - `여행 시작하기`로 `/map`에 이동한다.
- 주변 추천 장소
  - 현재 위치 기준 반경 1.5km의 반려동물 동반 장소를 거리순으로 표시한다.
  - 장소 이미지, 이름, 주소, 거리, 평점, 리뷰 수, 반려동물 정책 존재 여부를 제공한다.
  - 가로 스크롤과 마우스·펜 드래그 관성 이동을 지원한다.
- HOT 게시글
  - 추천 수 기준 인기 게시글 최대 3개를 표시한다.
  - 대표 사진, 제목, 작성자, 날짜, 추천 수, 댓글 수를 제공한다.
  - 항목 선택 시 `/community?post={ID}` 상세로 이동하고 `더보기`는 게시판으로 이동한다.
- 홈 요약, 주변 장소, HOT 게시글, 날씨는 서로 독립적으로 로딩·실패·재시도 상태를 처리한다.

## 6. 지도 및 여행 — `/map`

`/map`은 한 URL 안에서 다음 5단계 화면을 전환한다.

`경로 설정 → 코스 옵션 → 추천 코스 확인 → 여행 진행 → 여행 기록 완성`

진입 시 서버의 진행 중 코스를 조회하며, 활성 코스가 있으면 새 계획 화면 대신 여행 진행 단계로 복원한다.

### 6.1 경로 설정

- 출발지와 도착지를 각각 검색하고 선택한다.
- 두 글자 이상 입력하면 300ms 디바운스 후 내부 TMAP 장소 검색 API를 호출한다.
- 현재 위치가 확보된 경우 `현재 위치 사용`으로 출발지를 설정할 수 있다.
- 최근 검색 장소를 브라우저 로컬 저장소에 보관하고, 다시 선택·개별 삭제·전체 삭제할 수 있다.
- 저장된 최근 장소는 선택 시 최신 좌표와 정보로 다시 확인한다.
- 지도에서 선택한 위치를 확인한다.
- 출발지와 도착지를 모두 선택해야 다음 단계로 이동한다.

### 6.2 여행 코스 만들기

- 고정된 출발지와 최종 도착지 정보를 확인한다.
- TMAP 보행자 경로 API로 두 지점 사이 최소 도보 소요 시간을 계산한다.
- 등록된 반려동물 목록에서 함께 여행할 반려동물을 선택한다.
- 선택한 반려동물, 출발지, 최종 도착지, 여행일, 가능한 경우 목적지 날씨를 사용해 `/courses`에 코스 생성을 요청한다.
- 날씨 조회가 실패해도 날씨 정보 없이 코스 생성을 계속한다.
- 최종 도착지는 고정하고 서버가 반려동물과 날씨에 맞는 중간 경유지를 구성한다.
- 반려동물이 없거나 조회에 실패한 경우 코스를 생성할 수 없다.

### 6.3 추천 코스·장소 순서 확인

- 지도에 출발지, 중간 방문지, 최종 도착지 마커를 표시한다.
- 방문 순서에 맞춘 TMAP 보행 경로를 표시하고 전체 거리와 예상 시간을 제공한다.
- 경로 선 조회에 실패해도 추천 장소 순서는 확인할 수 있다.
- 각 장소 카드를 펼치면 다음 정보를 지연 조회·표시한다.
  - 추천 이유
  - 주소, 영업시간, 연락처, 카테고리
  - 평점, 리뷰 수, 방문 수
  - 반려동물 이용 조건
- `이 코스로 여행 시작`을 누르면 여행 진행 단계로 이동한다.

### 6.4 여행 진행

- 지도에 현재 위치와 방문 순서를 표시한다.
- 진행률, 방문 완료 수, 전체 장소 수, 다음 장소까지의 거리를 제공한다.
- 다음 장소의 `방문 체크인`으로 프런트 여행 진행 상태에 방문 완료를 기록한다.
- 방문 완료한 장소에 한해 다음 기록을 입력할 수 있다.
  - 장소별 간단 후기
  - 1~5점 만족도
  - 장소별 사진 최대 10장 추가 및 삭제
- 후기와 사진 선택 상태는 여행 중 프런트 메모리에 임시 저장된다.
- 마지막 `여행 완료` 시 선택한 사진의 메타데이터를 정리하고 업로드 URL 발급, 저장소 업로드, 사진 등록을 일괄 수행한다.
- 뒤로 가기를 누르면 여행을 종료하지 않고 홈으로 이동할 수 있으며, `/map` 재진입 시 서버 활성 코스로 복원할 수 있다. 아직 전송하지 않은 임시 사진은 사라질 수 있음을 안내한다.
- `중도 종료`는 확인 후 서버 코스를 삭제하고 작성 중 후기와 임시 사진을 초기화한다.

현재 구현 참고:

- 체크인은 현재 임시 제품 모드로, 방문 장소 ID를 프런트 `localStorage`에 최대 24시간 보관한다.
- 서버의 `/course-places/{coursePlaceId}/visit` 방문 인증은 현재 연결되어 있지 않아, 서버 방문 기록과 지역 스탬프 발급은 프런트 체크인으로 증가하지 않는다.
- 외부 장소 ID가 없는 사용자가 입력한 최종 도착지는 서버 방문 API를 호출하지 않고 클라이언트에서 방문 완료 처리한다.

### 6.5 여행 기록 완성

- 여행 제목을 편집한다. 기본값은 `{반려동물}와의 {도착지} 여행`이다.
- 출발지·도착지, 여행 날짜, 날씨, 방문 장소 수를 요약한다.
- 장소별 후기, 별점, 사진을 확인한다.
- 여행 사진 중 앨범 대표 사진을 선택한다.
- 전체 여행 일기를 작성한다.
- `앨범에 저장하기`
  - 내용과 별점이 모두 입력된 장소별 후기를 `/reviews`에 저장한다.
  - 모든 장소 후기 저장 후 `/courses/{id}/complete`로 코스를 완료 처리한다.
  - 대표 사진 선호를 로컬에 저장하고 `/album`으로 이동한다.
- `게시판 공유`
  - 여행 제목, 전체 일기, 코스 ID, 반려동물, 대표 사진을 여행 리뷰 게시글로 등록한다.
  - 사진이 로컬 URL인 경우 게시글용 사진 업로드를 별도로 수행한다.
- `SNS 카드`
  - 대표 사진, 여행 제목, 경로, 경유지, 날씨, 반려동물 정보를 카드 형태로 미리 본다.
  - Web Share API가 있으면 시스템 공유 시트를 열고, 없으면 공유 문구를 클립보드에 복사한다.

### 6.6 지도 오류 화면

`/map?error={type}`으로 다음 오류 상태를 직접 표시할 수 있다.

| 값 | 안내 및 동작 |
| --- | --- |
| `location-request` | 위치 권한 필요 안내 및 권한 허용 재시도 |
| `location-denied` | 주소 직접 입력 안내 및 위치 설정 팁 |
| `weather-failed` | 날씨 재시도 또는 날씨 없이 계속 진행 |
| `no-routes` | 목적지·출발지 변경 안내 |
| `no-places` | 다른 지역 선택 안내 |

공용 오류 화면에는 `upload-failed`, `session-expired` 구성도 구현되어 있지만 현재 `/map` 쿼리에서는 허용하지 않는다.

## 7. 게시판 — `/community`

### 7.1 게시글 목록

3개의 탭을 제공한다.

| 탭 | 조회 방식 | 특징 |
| --- | --- | --- |
| HOT | `sort=popular` | 추천 수 기준 재정렬, 첫 글 HOT 표시 |
| 자유게시판 | `sort=latest`, `type=GENERAL` | 글쓰기 제공 |
| 여행 리뷰 | `sort=latest`, `type=TRAVEL_REVIEW` | 여행 코스와 연결된 게시글만 표시 |

- 게시글 대표 사진, 제목, 작성자 프로필, 작성일, 추천 수, 댓글 수를 표시한다.
- 커서 기반 `더 불러오기`를 제공하며 중복 게시글을 합치고 같은 커서 반복을 방지한다.
- 목록의 초기 로딩, 빈 목록, 추가 로딩 실패를 각각 처리한다.
- 개발 데모 세션에서는 실제 API 대신 목 데이터를 사용하는 별도 게시판을 표시한다.

### 7.2 게시글 상세 — `/community?post={ID}`

- 게시글 사진 갤러리, 전체 화면 사진 보기, 이전·다음 사진 이동, 확대·축소를 제공한다.
- 제목, 카테고리, 작성자 프로필, 작성일, 조회 수, 본문을 표시한다.
- 여행 리뷰 글은 연결된 코스를 조회해 출발지·도착지, 여행일, 방문 순서를 함께 표시한다.
- 게시글 추천·추천 취소, 북마크·북마크 취소를 제공한다.
- 댓글 영역으로 부드럽게 이동할 수 있다.
- 광고·스팸 신고 사유를 입력해 신고할 수 있다.
- 본인 글은 `수정하기`와 삭제 기능을 제공한다.
- 삭제는 확인 모달을 거치며 완료 후 이전 화면으로 돌아간다.

### 7.3 댓글·답글

- 댓글 목록과 계층형 답글을 표시한다.
- 댓글과 답글을 작성한다.
- 본인이 작성한 댓글은 수정·삭제할 수 있다.
- 부모 댓글 삭제 후 서버가 반환한 실제 댓글 트리를 다시 조회한다.
- 목록 로딩 또는 오류 중에는 쓰기 동작을 잠그며, 성공한 쓰기와 댓글 수 재조회 실패를 분리해 처리한다.

## 8. 자유게시판 글 작성·수정 — `/community/write`

### 8.1 새 글 작성

- 제목과 본문을 입력한다.
- 현재 임시 제한은 제목 100자, 본문 100자다.
- 사진을 최대 10장, 한 장 및 전체 합계 각각 250MB 이하로 첨부한다.
- 지원 이미지 여부를 검사하고 업로드 전에 위치·촬영정보 등 메타데이터를 제거한다.
- 사진 삭제와 좌우 순서 변경을 제공하며 첫 번째 사진을 대표 사진으로 사용한다.
- 미리보기와 편집 모드를 전환한다.
- 메모리 기반 임시 저장을 제공하고 같은 로그인 세션의 페이지 이동 동안 유지한다.
- 게시 성공 후 초안을 지우고 자유게시판으로 돌아간다.
- 사진 일부 업로드 성공 후 실패한 경우 성공 상태를 보존하고 실패한 사진만 재시도한다.
- 새로고침으로 초안이 사라질 수 있을 때 브라우저 이탈 경고를 표시한다.

### 8.2 글 수정

- `/community/write?edit={ID}`로 기존 글을 불러온다.
- 본인 소유 게시글인지 확인한 뒤에만 편집 화면을 표시한다.
- 제목·본문·사진 추가·삭제·순서 변경을 지원한다.
- 기존 사진의 재사용 키를 확인할 수 없으면 사진 유실을 막기 위해 사진 편집을 잠그고 텍스트만 저장한다.
- 네트워크·타임아웃으로 수정 성공 여부가 불명확하면 게시글을 다시 조회해 반영 여부를 확인하고 중복 수정을 방지한다.
- `from=detail`이면 저장 또는 취소 후 브라우저 이전 상세 화면으로 돌아간다.

## 9. 여행 앨범 — `/album`

### 9.1 앨범 목록

- 사용자 앨범과 완료 코스를 함께 조회한다.
- 완료된 코스는 사진이 없어도 앨범 카드로 만든다.
- 최신 여행일부터 정렬한다.
- 총 여행 횟수와 총 사진 수를 요약한다.
- 2열 그리드로 여행일, 반려동물 이름, 대표 사진, 사진 수를 표시한다.
- 한 번에 20개씩 표시하고 목록 하단 접근 시 다음 20개를 자동으로 노출한다.
- 여행 완료 시 선택한 대표 사진이 서버 앨범에 존재하면 해당 사진을 첫 표지로 우선 표시한다.
- 특정 장소에 연결되지 않은 개인 사진은 `externalPlaceId=null`로 받아도 앨범 목록과 표지에 포함한다.

### 9.2 앨범 상세

- 선택한 앨범의 코스, 장소별 후기, 앨범 사진을 조합해 표시한다.
- 여행 후기를 게시판에 공유하면 커뮤니티의 여행 후기 게시판으로 이동한다.
- 반려동물, 여행 날짜, 당시 날씨, 전체 여행 일기를 제공한다.
- 출발지부터 도착지까지 방문 순서를 타임라인으로 표시한다.
- 장소별 사진과 촬영 수를 제공하며 3장 이후 사진은 펼치기·접기가 가능하다.
- 사진을 전체 화면으로 열어 이전·다음 이동과 확대·축소를 할 수 있다.
- 여행 리뷰 게시글 중 같은 코스의 최신 글을 찾아 전체 여행 일기로 표시한다.
- 여행 완료 화면에서 게시판에 공유하지 않은 경우, 저장된 전체 여행 일기를 불러오거나 공유 창에서 새로 작성해 여행 리뷰 게시글로 공유할 수 있다.
- 이미 같은 코스의 여행 리뷰가 확인되면 공유 완료 상태로 표시해 중복 등록을 막는다.
- 개별 후기 API가 실패해도 코스와 사진만으로 앨범 상세를 계속 제공한다.

## 10. 내정보 — `/my`

### 10.1 내정보 메인

- 닉네임, 이메일, 프로필 사진을 표시한다.
- 프로필 사진을 새 이미지로 변경하거나 기본 프로필로 되돌린다.
- 사진 업로드 시 메타데이터를 제거하고 `/photos/upload-url` → 저장소 업로드 → `/photos` 등록 → `/users/me/photo` 연결 순서로 처리한다.
- 추억으로 보관하지 않은 반려동물 중 최대 3마리를 요약하고 나머지 마릿수를 함께 표시한다.
- 다음 메뉴를 제공한다.
  - 반려동물 관리
  - 여행 스탬프
  - 추억 앨범
  - 작성한 글
  - 게시글 북마크
  - 작성한 리뷰
- 로그아웃과 회원 탈퇴를 제공한다.

내정보 메인의 `여행km`, `방문지`, `스탬프` 요약 통계와 장소 위시리스트 진입 메뉴는 현재 UI에서 숨긴다. 스탬프 하위 화면은 실제 API 값을 사용한다.

### 10.2 반려동물 관리

- 추억으로 보관하지 않은 반려동물의 이름, 견종, 크기, 나이, 선호 활동을 표시한다.
- 반려동물 추가, 수정, 추억 보관을 제공한다.
- 편집 시 이름, 견종, 크기, 나이, 선호 활동을 입력한다.
- 견종·활동 선택지는 공개 API에서 조회하며 실패 시 재시도할 수 있다.
- 제거 버튼에서는 `추억으로 보관하기`만 제공하며 영구 삭제 기능은 노출하지 않는다.
- 추억으로 보관하면 반려동물 수정 API에 `isDie=true`를 전달하고, 성공 응답을 받은 뒤 관리 목록에서 숨기며 추억 앨범 대상으로 표시한다.

### 10.3 닉네임 변경

- 최대 20자의 새 닉네임을 입력한다.
- 현재 닉네임과 다르면 중복 확인 후 `/users/me`를 수정한다.
- 서버 응답에서 닉네임이 생략된 경우 내정보를 다시 조회해 실제 반영 여부를 확인한다.

### 10.4 내가 작성한 글

- 작성한 게시글의 대표 사진, 제목, 본문 일부, 날짜, 조회·추천·댓글 수를 표시한다.
- 항목 선택 시 해당 게시글 상세로 이동한다.
- `/my?section=posts`로 설정 패널 상태를 URL에서 복원할 수 있다.

### 10.5 장소 위시리스트

- 서버 연동 코드는 유지하지만 내정보 메뉴에서는 현재 진입점을 숨긴다.
- 위시리스트 ID 목록을 조회한 뒤 각 장소 상세를 최대 동시 4개씩 조회한다.
- 장소명, 주소, 평점, 리뷰 수를 표시한다.
- 개별 장소를 위시리스트에서 제거할 수 있다.

### 10.6 게시글 북마크

- 북마크한 게시글의 제목, 작성자, 작성일을 표시한다.
- 게시글 상세로 이동하거나 북마크를 해제할 수 있다.

### 10.7 내가 작성한 리뷰

- 작성한 장소 리뷰의 별점, 내용, 작성일을 표시한다.
- 현재 이 화면에서는 리뷰 조회만 제공하고 수정·삭제는 제공하지 않는다.

### 10.8 여행 스탬프

- `/users/me/stamps`에서 17개 광역자치단체의 스탬프 도감을 조회한다.
- 전체 수, 획득 수, 수집률과 남은 지역 수를 표시한다.
- 지역별 획득 여부에 따라 달성·미달성 PNG를 구분하고, 방문 횟수와 최초 획득일을 표시한다.
- 서버 응답의 지역명, 획득 상태, 방문 횟수, 획득일, 중복 항목을 검증한 뒤 표시한다.
- 로딩, 빈 도감, 오류, 재시도 상태를 독립적으로 처리한다.

### 10.9 추억 앨범

- 반려동물 목록에서 `isDie=true`인 반려동물만 추억 앨범 대상으로 표시한다.
- 반려동물을 선택하면 펫별 앨범 API로 함께한 여행 앨범을 조회한다.
- 앨범 목록과 상세 화면은 여행 앨범의 기존 UI와 상세 조회·게시판 공유 기능을 그대로 사용한다.
- 대상 반려동물이나 저장된 앨범이 없을 때 각각 빈 상태 안내를 표시한다.

### 10.10 계정 관리

- 로그아웃은 먼저 로컬 자격 증명과 세션 데이터를 제거한 뒤 서버 `/auth/logout`을 호출한다. 서버 로그아웃에 실패해도 로그인 화면으로 이동하고 다음 로그인 화면에서 실패 안내를 제공한다.
- 회원 탈퇴는 안내 확인 체크 후 `/users/me`의 계정 상태를 `WITHDRAWN`으로 변경하고 로그아웃한다.

## 11. 개발 전용 페이지

### 11.1 실시간 개발 진단 콘솔 — `/dev/diagnostics`

비프로덕션 환경에서만 접근할 수 있다.

- 다른 앱 탭에서 발생하는 Axios 요청·응답, 인증 상태 변경, 시스템 이벤트를 실시간 수집한다.
- 최대 200개 이벤트를 유지한다.
- 전체, NETWORK, STATE, SYSTEM 필터를 제공한다.
- 이벤트 수집 일시정지·재개와 로그 지우기를 제공한다.
- 이벤트 상세 JSON, 발생 시각, source, request ID를 표시한다.
- access token, registration token, Authorization, Cookie 값은 자동 마스킹한다.

### 11.2 추천 코스 미리보기 — `/preview/recommended-course`

개발 환경에서만 접근할 수 있는 UI 검수용 페이지다.

- 서울역 → 서울숲 예시 코스와 5개 장소를 고정 데이터로 표시한다.
- 정상 이미지, 이미지 누락, 이미지 로딩 실패, 이용 규칙 누락 등 다양한 UI 상태를 확인한다.
- 보행 경로, 장소 상세 시트, 리뷰 예시를 확인한다.
- `여행 시작`은 실제 여행을 생성하지 않고 미리보기 안내만 표시한다.

## 12. 구현되어 있으나 현재 사용자 라우트에 연결되지 않은 화면

### 12.1 최종 도착지 추천 선택 화면

`MapPlaceSelectionScreen`과 추천 장소 조회 API가 구현·테스트되어 있으나 현재 `/map`의 실제 플로우에서는 사용하지 않는다. 현재 플로우는 사용자가 검색 단계에서 지정한 최종 도착지를 고정하고 서버가 중간 경유지를 바로 생성한다.

미연결 화면이 제공하는 기능:

- 목적지 지역 주변 추천 장소를 지도와 카드 목록으로 표시
- 추천 이유, 상세 정보, 반려동물 이용 조건 확인
- 후보 한 곳 선택 후 해당 장소를 최종 도착지로 코스 생성

### 12.2 장소 리뷰 목록 화면

`ReviewList` 컴포넌트는 내 리뷰 조회·삭제, 장소 리뷰 조회, 추천·추천 취소 기능을 구현하고 있으나 현재 게시판 탭이나 별도 URL에 연결되어 있지 않다. 내정보의 `작성한 리뷰`는 별도의 읽기 전용 화면을 사용한다.

### 12.3 Storybook 화면

다음은 URL 페이지가 아니라 독립적인 디자인·상태 검증용 스토리다.

- 홈, 로그인, 회원가입, 커뮤니티, 여행 종료, 공용 오류 화면
- 모바일 셸, 상단 바, 하단 내비게이션
- 버튼, 입력창, 선택 칩, 아이콘 버튼, 메뉴 행, 모달 액션 등 공용 UI
- 디자인 토큰과 레거시 UI 감사 화면

## 13. 프런트엔드 내부 API 라우트

브라우저에 외부 서비스 키를 노출하지 않도록 다음 Next.js 서버 라우트를 사용한다.

| 내부 경로 | 메서드 | 역할 |
| --- | --- | --- |
| `/api/tmap/sdk` | GET | 서버의 `T_MAP_APIKEY`로 TMAP JS SDK를 가져와 키 노출 여부를 검사하고 브라우저에 전달 |
| `/api/tmap/pois` | POST | 검색어를 TMAP POI API에 전달하고 최대 10개의 정규화된 장소 반환 |
| `/api/tmap/routes/pedestrian` | POST | 출발지·도착지와 최대 3개 경유지의 도보 거리, 시간, 경로 좌표 반환 |
| `/api/weather/current` | GET | 기상청 격자 좌표의 현재 날씨를 정규화해 반환; 좌표가 없으면 기본 지점 사용 |

- TMAP 검색과 경로 응답은 저장하지 않으며 `no-store`로 처리한다.
- 날씨 성공 응답은 짧게 캐시하고, 오류 응답은 캐시하지 않는다.
- 외부 API 설정 누락, 잘못된 입력, 요청 과다, 타임아웃, 외부 응답 오류를 구분해 적절한 상태 코드와 사용자 메시지를 반환한다.
