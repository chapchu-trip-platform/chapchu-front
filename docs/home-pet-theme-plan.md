# 홈 대체 기능 기획: 반려동물 취향 기반 여행 테마

## 배경

홈의 `주변 추천 장소`는 기기 위치를 기준으로 반경 1.5km 안의 장소를 조회했다. 이 영역은 다음 이유로 제거한다.

- 홈 진입과 동시에 위치 정확도와 장소 API 상태에 영향을 받는다.
- 지도, 날씨, 여행 시작 영역과 위치 정보의 역할이 중복된다.
- 가까운 장소를 나열하지만 사용자가 왜 이 장소를 선택해야 하는지 설명하기 어렵다.
- 위치 권한이 없거나 정확도가 낮으면 홈의 주요 탐색 영역이 빈 상태나 오류 상태로 보인다.

이번 제거 범위는 홈의 위치 기반 장소 추천 UI와 그 전용 요청 로직이다. 홈 지도와 날씨, 지도에서의 출발지 설정처럼 다른 목적의 위치 기능은 유지한다.

## 제안 기능

### 이름

`반려동물 취향 기반 여행 테마`

### 핵심 가치

현재 위치가 아니라 등록된 반려동물의 활동 취향을 바탕으로 여행의 목적을 먼저 고르게 한다. 사용자가 테마를 선택한 뒤 지도 화면에서 출발지와 실제 방문 장소를 정한다.

예시:

- `느긋한 산책` — 산책을 좋아하는 반려동물을 위한 공원·산책로 중심
- `함께 쉬는 카페` — 실내 동반과 휴식을 중심으로 한 짧은 외출
- `신나는 물놀이` — 물놀이 활동을 선호하는 반려동물을 위한 테마
- `주말 드라이브` — 장거리 이동과 여러 장소 방문을 묶은 테마

## 사용자 흐름

1. 사용자가 홈에서 `루이가 좋아할 여행 테마` 영역을 본다.
2. 최대 3개의 테마 카드에서 추천 이유와 예상 활동 성격을 확인한다.
3. 테마를 선택하면 지도 여행 준비 화면으로 이동한다.
4. 지도 화면에서 출발지를 현재 위치, 검색 위치 또는 최근 검색 위치 중 하나로 정한다.
5. 선택한 테마는 장소 추천과 코스 생성의 초기 필터로 사용한다.

위치 권한 요청은 이 테마 영역을 보기 위해 필요하지 않다. 위치가 필요한 동작은 지도 흐름 안에서 사용자 선택과 함께 처리한다.

## 홈 화면 구성

기존 `여행 시작하기` CTA와 `HOT 게시글` 사이에 배치한다.

### 섹션 헤더

- 제목: `{대표 반려동물 이름}가 좋아할 여행 테마`
- 설명: `등록한 활동 취향을 바탕으로 골랐어요.`
- 보조 동작: `취향 수정` → 반려동물 관리 화면

### 테마 카드

각 카드에는 다음 정보만 제공한다.

- 테마 이름
- 한 줄 추천 이유
- 활동 태그 1~2개
- 분위기를 전달하는 이미지 또는 일러스트
- `이 테마로 떠나기` 동작

거리, 현재 위치, 주변 장소 개수는 홈 카드에서 표시하지 않는다.

### 상태별 처리

- 활동 취향이 있음: 일치도가 높은 테마를 최대 3개 노출한다.
- 활동 취향이 없음: `산책`, `카페`, `드라이브` 기본 테마와 `취향 등록하기` 동작을 노출한다.
- 반려동물이 여러 마리임: 대표 반려동물의 이름을 제목에 사용하고, 공통 활동을 우선한다. 공통 활동이 없으면 선택한 반려동물을 지도 화면에서 다시 정한다.
- 데이터 로딩 중: 카드 3개 크기의 스켈레톤을 노출한다.
- 데이터 오류: 홈 전체를 막지 않고 기본 테마를 노출하며 개인화되지 않았음을 짧게 안내한다.

## MVP 범위

### 포함

- 반려동물 활동 취향을 테마 ID로 변환하는 규칙
- 최대 3개 테마 카드
- 테마 선택 후 지도 여행 준비 화면으로 이동
- 선택한 테마를 지도 흐름에 전달
- 취향 미등록, 로딩, 오류 상태
- 모바일 가로 스크롤과 키보드 접근성

### 제외

- 홈에서 실제 장소 목록 조회
- 홈 진입 시 테마를 위한 위치 권한 요청
- AI 문구 생성
- 사용자 행동 기반 자동 학습
- 테마별 실시간 장소 수와 거리 표시
- 새로운 지도 SDK 또는 상태 관리 라이브러리 도입

## 데이터와 계약 제안

백엔드 계약이 확정되기 전까지 UI 모델과 API 응답 모델을 분리한다.

```ts
type TravelThemeId = 'walk' | 'cafe' | 'water' | 'hiking' | 'camping' | 'drive'

interface HomeTravelTheme {
  id: TravelThemeId
  title: string
  reason: string
  activityLabels: string[]
  imageUrl: string | null
}
```

MVP에서는 기존 반려동물 프로필의 활동 ID를 프론트엔드 매퍼로 테마에 연결할 수 있다. 백엔드가 홈 전용 추천 결과를 제공하게 되면 같은 UI 모델로 변환한다.

결정이 필요한 항목:

- 대표 반려동물을 서버에서 정할지, 프론트엔드에서 첫 번째 반려동물로 정할지
- 여러 반려동물의 취향을 교집합과 합집합 중 어떤 방식으로 반영할지
- 지도 화면이 받을 최소 파라미터를 테마 ID 하나로 제한할지
- 테마 이미지의 운영 주체와 기본 이미지 정책

## 완료 조건

- 홈에서 현재 위치 반경 기반 장소 목록이 보이지 않는다.
- 홈 진입 시 주변 장소 전용 API 요청이 발생하지 않는다.
- 지도와 날씨의 기존 위치 기능은 회귀하지 않는다.
- 취향 데이터가 없어도 사용자는 여행 테마를 선택해 지도 흐름으로 이동할 수 있다.
- 테마 선택은 실제 장소를 확정하지 않고 지도 화면의 초기 조건만 설정한다.
- 카드와 CTA는 현재 Warm Beige, Sage Green, Soft Orange 디자인 토큰을 사용한다.
- 작은 모바일 화면에서 가로 스크롤이 세로 스크롤을 방해하지 않는다.
- 테마 카드와 이동 동작에 접근 가능한 이름과 포커스 표시가 있다.

## 검증 지표

- 홈에서 지도 여행 준비 화면으로 이동한 비율
- 테마 카드 노출 대비 선택 비율
- 테마 선택 후 코스 생성 완료율
- 위치 권한 거부 사용자와 허용 사용자의 여행 시작 전환율 차이
- 취향 미등록 사용자의 `취향 등록하기` 완료율

## 구현 순서

1. 기획·디자인에서 테마 종류, 카드 문구, 이미지 정책을 확정한다.
2. 프론트엔드와 백엔드가 반려동물 활동 데이터의 소유 계약을 확정한다.
3. 테마 ID와 UI 모델, 활동-테마 매퍼를 추가한다.
4. 홈 섹션과 상태별 UI를 구현한다.
5. 지도 여행 준비 화면에서 테마 ID를 받고 초기 필터에 반영한다.
6. 단위 테스트, 홈 화면 테스트, 지도 연결 테스트를 추가한다.
7. 이벤트 이름과 개인정보 비수집 조건을 확인한 뒤 점진적으로 노출한다.

## 주요 위험과 대응

- 취향 데이터가 오래됨: 카드에서 `취향 수정`을 항상 접근 가능하게 한다.
- 추천 이유가 과장됨: 실제 프로필 활동과 연결되는 정해진 문구만 사용한다.
- 지도 결과가 테마와 맞지 않음: 테마 ID를 장소 검색 필터와 연결하는 계약을 출시 전에 검증한다.
- 개인화 실패가 홈 오류로 확대됨: 기본 테마를 독립적으로 제공해 홈을 계속 사용할 수 있게 한다.
